# Optional Adoption Record

This is a small, optional provenance record for later updates. It is not an executable profile, a hidden loader, or a competing instruction authority. Effective preferences must be written into the approved target instructions; future coding threads should work without this record or the source repository.

## Contents and ownership

Before creating a record, agree on its exact location, visibility, and write scope. It may be private or repository-owned at the user's choice; creating it is separate from policy adoption. Do not persist a transcript, credentials, private network details, unnecessary hardware inventories, or concrete model mappings the user did not request to save.

Useful fields:

| Field | Meaning |
|---|---|
| Scope and target | Exact user/project scope and effective instruction file |
| Source | Selected repository/path and commit/release; mark uncommitted draft explicitly |
| Language | Runtime language and any separately maintained companion |
| Modules | Adopted, conditional, or omitted, with reasons |
| Decisions | Question ID, value, provenance, scope, and whether explicit or proposed-and-approved |
| Deferred values | Why unknown; exact adopted conditional fallback, without implied permission |
| Model research, if requested | Exact exposed identity/provider, evidence sources and check date, uncertainty, approved mapping/fallback; distinguish research from selection |
| Interactive execution | Approved tool/model/context choices, direct-use authority, progress/stop budget, supported media/retention controls and unknowns |
| Environment decisions | Detected shell/encoding/Git facts, accepted or declined recommendations, retained-environment recovery approach |
| Recovery | Backup location, base identity, restore scope, verified integrity |
| Applied state | Exact approved changes, target hash, validation, pending human acceptance |

## Example

An illustrative record might state:

```text
Scope: project
Target: AGENTS.md
Source: user-selected local policy checkout, reviewed commit recorded at adoption
LANGUAGE-01: Simplified Chinese; explicit in the adoption request
SUBAGENT-01: disabled; existing project instruction, unchanged
Browser route: structured tool where allowed; otherwise ask for a scoped exception
Media numeric budget: deferred; inspect size, keep originals, send small review copies
Writes: policy diff approved; Skill installation not requested
```

The example is not a default profile. In particular, disabling delegation must not silently enable the primary Agent's interactive browser use.

## Updates

Reconcile the record with current instructions and facts before using it. If it is missing, continue from the actual target and available source; do not replay adoption merely to reconstruct bookkeeping. If it conflicts, treat it as a lead to investigate, not authority to overwrite the user's policy.

Research observations can become stale without invalidating every adopted rule. Refresh only affected evidence and decisions when requested or necessary; do not copy volatile price tables into runtime instructions or rerank models at every thread start. Never save credentials or private deployment identifiers as public research provenance.
